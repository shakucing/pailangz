# Navigation, mobile and security review

Scope: the repository implementation and read-only measurements of the existing Vercel deployment. Changes described here require migration 010 and a new deployment to affect the live site. This is a source/control review with regression tests, not a penetration test or certification.

## Performance findings and changes

The saved production database endpoint is in AWS `ap-southeast-1` (Singapore). A public `/staff` response had `x-vercel-id: sin1::iad1::…`: the request entered Singapore but its Node function ran in Virginia. Database-heavy pages therefore paid for repeated cross-region calls. `vercel.json` now sets `regions: ["sin1"]`. Vercel recommends placing functions near the database: [Vercel regions](https://vercel.com/docs/regions).

Before changes, a read-only three-request sample from this computer measured the public homepage at **6,062 ms** on the first request and **1,421–1,427 ms** on subsequent requests. The tournament list completed in **721–763 ms** and the login page in **289–301 ms**. The same local optimized build completed warm homepage requests in **26–31 ms**. These are complete HTTP response times, not browser interaction/LCP measurements or production load-test guarantees. They support the region/network diagnosis; staff-page measurements require an authorized existing session or isolated synthetic test environment.

Previously the fixture workspace fetched every stage and round, all 192 match forms, every result/evidence history and hidden standings at once. Closing HTML details panels did not stop server work, transfer or hydration. The new workspace selects a stage and round, keeps its lightweight complete fixture preview collapsed, and loads **eight match editors** per page with opponent and status filters. Current standings are requested explicitly. Participant/team lookups are limited to that tournament. Staff accounts are paginated at 20 and initially show active accounts, keeping suspended QA entries out of routine work.

Staff navigation now lives in a shared layout and remains usable while content streams. Localized public and staff loading states, plus pending-link indicators, acknowledge navigation. Private data and permissions are still rechecked on every page/API request; render-scoped React memoization deduplicates layout/page checks without caching authorization across requests. Session identity and revocation are read in one query, and transaction context uses one query instead of two. Migration 010 changes constant RLS permission calls into scalar subqueries, allowing PostgreSQL to evaluate each check once per statement instead of once per row. Protected content remains uncached. Prefetching does not write misleading workspace-view events.

An isolated in-memory PostgreSQL-compatible benchmark loaded migrations 001–009 and 10,000 synthetic member rows, measured an authenticated `EXPLAIN (ANALYZE, FORMAT JSON) SELECT count(*) FROM "Member"`, then applied migration 010 and repeated the same query. Warm execution times fell from **105.164–123.560 ms** to **3.845–4.828 ms**. Both queries retained the same permissions/data semantics. This isolates the row-policy improvement; it is not a live-site speed or load-test claim.

The landing page uses native IntersectionObserver/Web Animations rather than shipping GSAP/ScrollTrigger; decorative animation is skipped on phones and with reduced motion. Mobile staff screens have a compact expandable menu, 44 px controls, 16 px form text, bounded scrolling for tables, wrapping identities and grids with zero minimum column widths. Account creation/editing are collapsed until requested. Actual viewport findings are recorded in `verification.md` after browser review.

## OWASP Top 10:2025 review

Categories follow the current [OWASP Top 10:2025](https://top10.owasp.org/2025/).

| Category | Controls and verification |
| --- | --- |
| A01 Broken Access Control | Server checks current role, account suspension, expiry, session version and revocation. Private transactions also check the database session/RLS. New staff functions independently require admin access, reject self changes and protect the last admin. No direct runtime staff-write grants. Anonymous/private-ID, moderator and forged-role regressions exercise denial. |
| A02 Security Misconfiguration | Non-owner runtime role; deployment/database tier checks; HTTPS/TLS and private storage requirements in production. Nonce CSP, framing denial, MIME sniffing protection and private no-store headers. Migration function grants revoke public execution and fix their search path. Owner credentials remain outside runtime config. |
| A03 Software Supply Chain Failures | Production audit initially reported four advisories: csv-parse, deepmerge-ts and two mysql2 advisories. Updated csv-parse to 7.0.3; pinned patched transitive deepmerge-ts 8 and mysql2 >=3.23.1. Re-audit reports zero known production advisories. Lockfile and registry supply-chain verification passed. CLI/build compatibility and import regression checks remain part of the combined build. |
| A04 Cryptographic Failures | AES-256-GCM with fresh nonce and context AAD encrypts private contacts/evidence. bcrypt cost 12 protects passwords; creation/provisioning enforce 14-character minimum and 72-byte maximum. Credentials/hashes never reach account lists or audits. Encryption and contextual tampering tests cover these boundaries. |
| A05 Injection | Prisma/parameterized SQL throughout account writes and request context. Zod bounds and enums validate input. CSV parser upgraded; imports bound record sizes and reject duplicate headers. React escapes text; audit CSV neutralizes spreadsheet formula prefixes. No untrusted raw SQL identifiers. |
| A06 Insecure Design | Explicit privilege boundaries and current-session checks; audit/write atomicity; staff self/last-admin safeguards; deleted actors' audit/result history retained. Published readiness, accepted-result immutability, disputes/restarts and evidence acceptance remain controlled. Removing routine reasons does not remove the audit trail. |
| A07 Authentication Failures | Password-only policy retained per user instruction. Independent eight-hour revocable sessions, email/deployment login throttles, credential consistency recheck during login and immediate session revocation on staff edits. No public account provisioning/reset endpoint. New creation rate limit bounds bcrypt work. |
| A08 Software or Data Integrity Failures | Append-only audit triggers; immutable accepted results; idempotency, foreign keys, unique member/team constraints and serializable mutations. Account mutation rolls back if its audit fails. Signed/timestamped webhook ingestion remains disconnected until an integration actor is provisioned. |
| A09 Security Logging and Alerting Failures | Transactional actor/target/change records for account actions; credential/contact redaction; audited private access and failed authenticated operations. Auth diagnostics log known codes without metadata. Hosting-level alert routing, independently retained logs and backup restoration require operator verification; an unavailable database cannot store its own outage audit. |
| A10 Mishandling of Exceptional Conditions | Streaming byte limits apply even with absent/false Content-Length; oversized/malformed JSON/multipart requests receive 413/400. Evidence signature/type/size validation, bounded lists, generic API errors, serialization conflict handling and rollback tests. Database failures reach retry UI rather than being misreported as a login redirect. |

## Release verification

Use an isolated database for account/security regression tests. Never use a production connection for test seeding or account benchmarks. Creation/deletion tests must remove their entire disposable database afterward; shared previews can be inspected using the human's existing signed-in session.

The combined production build, TypeScript check, **116 unit tests**, **45 isolated native PostgreSQL integration checks**, and **18 isolated HTTP workflow checks** passed. The HTTP suite passed with both native PostgreSQL and the default PGlite transport. Its runner creates its own database, server and credentials, then removes them and test uploads. HTTP coverage includes both staff roles, reason-free account management, revocation, privilege denials, bounded malformed/chunked requests, private-data leakage and cross-origin mutations. Loaded staff screens at **320, 390 and 768 px** had no horizontal overflow; narrow account and match editors were checked expanded. Public home, tournaments, registration and login screens were also checked at those widths, with immediate navigation feedback and no browser error/warning logs.

The production latency improvements must be measured again after migration 010 and the Singapore deployment. No production deployment, schema change, staff deletion or performance load test is implied by the local review.
